## Reproduction

Use a committed checkout with Docker, Supabase CLI 2.109.1, PostgreSQL tools,
Deno, Swift and Python 3 installed:

```sh
./scripts/weekly-local-verify.sh
```

The script creates a unique disposable local Supabase project on loopback
ports `57320`–`57329`, copies only tracked test inputs, writes a SHA256 input
manifest and source commit, resets that disposable database from migrations,
runs all portable suites and the persisted weekly lifecycle smoke, then stops
only its own project. The temporary source, manifest and logs remain at the
printed path. Choose `WEEKLY_VERIFY_PORT_BASE` if those ports are occupied;
`--keep-stack` intentionally leaves only that disposable project running.
No local `.env`, linked-project state or generated build directory is copied.
This does not reset the original development database on `54322`.

Native verification additionally needs Xcode and an available iOS Simulator.
The local toolchain differs from the pinned CI Xcode 26.2 toolchain; CI results
must be reported separately. See [native reproduction and evidence](WEEKLY_NATIVE_V1_ACCEPTANCE.md).
