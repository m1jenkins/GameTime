Where the work went

Merged does not currently mean visible

The critical product gap is the last mile: navigation, onboarding, truthful source state, primary create actions, and a coherent default journey were never made the delivery target.

What is on-screen now

Every symptom has a concrete explanation

Confirmed UX bug

“70,000 steps to finish the day”

The open Personal challenge is cumulative: 70,000 across the week. The Today hero makes that weekly total dominant, while the lower pace panel correctly computes a 10,000-step day and 2,650 remaining today. The stored target is not corrupted in the reproduction; the screen hierarchy is.

Behavioral trap

No way to create a challenge

The normal create button appears only when there is no open Personal challenge. An existing 70,000-step challenge occupies that single slot. Friend-week creation lives in a separate internal route that normal launch does not expose.

Missing product flow

No onboarding process

There is a one-screen name/username setup for a newly authenticated account with no profile. Existing accounts never see it, and there is no onboarding for the new friend-challenge direction, Apple Health expectations, invitations, or product selection.

Misleading state label

Apple Health “connects” instantly

The implementation treats completion of Apple’s authorization request as connected. If the person has already answered the prompt, that call can return immediately. Apple does not reveal read denial directly, but the app still upgrades the label to “Health connected” before it proves that a usable read occurred.

Confirmed render bug

Blank cards around Time zone

The two blanks are the two Divider views. DaybreakCard styles multiple sibling views without first wrapping them in a VStack, so the runtime lays out and backgrounds the dividers as separate cards. This code predates the recent product work.

What the commits genuinely accomplished

A strong engine, not a product conversion

Substantial and real

  • New private database domains for duels, commitments, weekly friend groups, and community weeks.
  • Immutable consent, exact retry recovery, account isolation, correction/review windows, safe exits, and simulated outcomes.
  • Internal Swift screens and clients for the new domains.
  • Large automated coverage across SQL, Deno, Swift, UI fixtures, and authenticated local HTTP.

Not accomplished

  • The default app was not changed from Personal to friend challenges and commitments.
  • The normal navigation does not advertise the new products.
  • Apple Health is not connected to weekly scoring.
  • The current visible Personal bugs were not part of the acceptance gate.
  • No physical-device, human, pilot, hosted, notification, or funded rollout was completed.

Evidence: PROJECT_MEMORY.md, PLAN.md, docs/WEEKLY_EXECUTION.md, docs/WEEKLY_LOCAL_ACCEPTANCE.md, current source, Git history, and a fresh simulator build from 577bc32.

Later gates
Bottom line

We completed infrastructure-heavy slices while leaving the launch experience largely untouched.

The codebase is much more capable than it looks, but the current app is an honest reflection of what was productized: almost none of the pivot. The next milestone should be judged by a visible end-to-end friend challenge in the default internal build—not by another large test count.
