A lost HTTP response does not lose the work.

The scheduler first saves an invocation. The Edge handler loads its saved claims, completes each item in a separate transaction, then saves an aggregate result.

  1. Cron tickSave invocation, then commit.
  2. Edge functionAuthenticate and load saved claims.
  3. Separate completionsFive lanes call PostgREST and commit SQL receipts.
  4. Saved resultReturn allowlisted counts and state.

One active run

A database lease prevents overlapping runs. Duplicate requests reuse saved claims; expired claims need a fresh invocation. Stale tokens cannot overwrite later results.

Bounded work

Local defaults: 20 items, five completion lanes, five-second RPC timeout, 50-second request budget and 60-second run lease. Existing retry and dead-letter limits remain.
